# セキュリティの点検（2026-11-27）

公開（2027-01-12）の前に、Claude Code が点検した結果。あなた（開発者）の依頼による。

## 問題なし（確かめたこと）

| 項目 | 結果 |
|---|---|
| 秘密の鍵 | 今のファイルにも、Gitの履歴にも、秘密の鍵（Stripe の sk_・whsec_、Gemini の AIza…、Anthropic の sk-ant-、Supabase の secret・service_role、秘密鍵ファイル）はなかった。アプリに入っているのは公開してよい鍵（Supabase の sb_publishable_、PostHog の phc_）だけ |
| データベースの権限（RLS） | 有料かどうか（profiles）は本人も読むだけで書き換えられない。同期データは有料の本人だけが読み書きできる。AIの回数は本人が減らせない |
| AIで調べる（ai-search） | ログインの確認、今月の回数の確認、入力は1〜100文字 |
| 支払い（billing） | ログインの確認、戻り先URLは決めた先だけ、Stripe からの知らせは署名・時刻（5分以内）を確かめる（比べ方も時間で漏れない方法）、有料の人はもう一度買えない |
| 画面 | HTMLを直接入れる書き方（innerHTML など）・eval はない。文字は React が安全に表示する |
| 使っている部品 | npm audit で知られた弱点 0件 |
| バックドア（隠れた入口） | GitHub Actions は公式の部品だけで、秘密の値を使っていない。ビルドの設定に知らない処理はない。部品のインストール時の処理は core-js（寄付のお願いを表示するだけ）のみ |
| 通信の送り先 | Supabase・PostHog（EU）・Wikipedia（日本語・英語）・ウィクショナリー・Google（「調べる」ボタン）だけ |

## 直したほうがよいもの

| # | 重さ（意見） | 内容 | 直し方の案 |
|---|---|---|---|
| 1 | 中 | AIの回数は「結果が出たあとに数える」ので、同じ人が同時にたくさん送ると、上限を超えてAIが動く（AIの料金が増える） | 送る前に1回分を数え、AIが失敗したら取り消す。取り消しは関数（サーバー）だけができるようにする。SQLの実行（あなた）と関数の配置が要る |
| 2 | 小 | 出典のURLに「javascript:」などが入る余地がある（手入力・AIの結果・バックアップ）。React 19 が止めるが、アプリ側でも止めるほうが安全 | 出典のリンクは http・https だけ開く |
| 3 | 小 | 同期データの大きさに上限がない（有料の本人だけが書ける） | データベースで上限（例：20MB）を決める |
| 4 | 小 | GitHub Actions の部品を「v4」のような版の名前で指定している（部品の持ち主が中身を差し替えると影響を受ける） | 版を中身の番号（コミットのSHA）で固定する |
| 5 | 小 | 読み込める送り先を決める仕組み（CSP）がない | ページに CSP を書く（GitHub Pages では meta タグで書く） |
| 6 | 小 | 関数のエラーに、Stripe・Gemini のエラーの文が一部そのまま出る | 画面には短い説明だけを返し、詳しくは記録（ログ）にだけ残す |

## あなたに確かめてほしいこと（設定の画面にあり、Claude Code からは見えない）

- Supabase の認証の設定：メールの確認を必須にしているか、パスワードの最低文字数、漏れたパスワードを使えなくする設定（Leaked password protection）
- GitHub・Supabase・Stripe・Google（Gemini）・PostHog のアカウントの2段階認証
- Supabase の Management API の鍵（claude-code-4）は、使い終わったら取り消す
