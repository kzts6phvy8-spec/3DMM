# 第1層：戦略（Strategy）

状態：**確定候補**（利用者の回答を反映済み。最終確認待ち）

戦略の層では、2つの問いに答える。

- **ユーザーニーズ**：使う人は何を求めているのか
- **プロダクトの目的**：このプロダクトは何を実現するために存在するのか

---

## 1-0. 原点：知ることの幸福（利用者自身の言葉）

> 私にとって、知ることは単なる情報の獲得ではない。
>
> 知識を得ることには、それ自体に心地よさがある。人間にとって、世界を知ることは何らかの幸福をもたらすものなのではないかと思う。
>
> 特に、別々に存在していた知識同士がつながる瞬間が好きだ。
>
> 新しい知識を得たというよりも、以前から知っていたことの意味を、別の角度から再発見したような感覚。バラバラだった世界の断片が結びつき、今まで見えていなかった構造が浮かび上がる感覚。
>
> 知識が増えることで、世界そのものが変わるわけではない。しかし、世界から読み取れるものは確実に増えていく。
>
> 今まで何気なく見ていたものに背景が生まれ、無関係だと思っていたものに関係性が見つかる。世界の解像度が上がっていく。
>
> 私は、その体験を素晴らしいと思っている。
>
> Knowledge Cosmosは、知識を効率よく管理するためだけの道具ではない。知ることの喜びや、知識がつながる心地よさを、視覚的にも体験できる場所にしたい。

この文章は、すべての層の判断基準の最上位に置く。
機能や見た目で迷ったら、「それは知ることの幸福を深めるか」で判断する。

## 1-1. 一言で言うと

> **確かな知識が星となってつながり、世界の解像度が上がっていく体験をくれる宇宙。**

## 1-2. マインドマップとの違い（出発点の再定義）

トニー・ブザンのマインドマップから出発するが、構造の前提が違う。

| | マインドマップ（ブザン） | Knowledge Cosmos |
|---|---|---|
| 中心 | 1つのテーマが中心にある | 中心がない。どの知識も中心になりうる |
| 形 | 放射状の木構造（親→子） | 網の目（ネットワーク） |
| 範囲 | 1枚＝1テーマ | 1つの宇宙＝自分の知識すべて |
| つながり | 枝分かれのみ | 分野をまたいで自由につながる |
| 線の意味 | 「下位にある」だけ | 因果・類似・対立など、つながりの**意味**を持つ |
| 使う時 | 考えを広げる・整理する（一時的） | 知識を蓄え、眺め、再発見する（継続的） |

マインドマップから受け継ぐもの：

- 視覚で考えること
- 放射的な連想
- 色や大きさで重要度を表すこと

捨てるもの：

- 単一の中心
- 木構造という制約

## 1-3. ユーザー

- **初期ユーザー**：自分自身（1人）
- **主な端末**：iPhone（まずWeb版、後でアプリ化）
- **ユーザー像**
  - 知ることそのものに喜びを感じる人。
  - 特に、別々の知識がつながる瞬間が好き。
  - 勉強のためだけではなく、暇なときにふと開いて眺めたい。
  - 知識の正しさを大切にする。事実だけを、出典つきで残したい。
  - 興味の分野は限定しない（勉強・読書・仕事・趣味・ニュース・雑学のすべて）。
  - プログラミングは初心者。

## 1-4. ユーザーニーズ

この製品は「困りごとを解決する道具」ではない。「喜びを生む場所」として設計する。
そのため、ニーズを「得たい体験」として定義する。

| # | 得たい体験 | 原点の言葉との対応 |
|---|---|---|
| N1 | **つながる瞬間**：別々の知識が結びつき、隠れていた構造が見える | 「別々に存在していた知識同士がつながる瞬間が好きだ」 |
| N2 | **再発見**：知っていたことの意味を、別の角度から見直す | 「以前から知っていたことの意味を、別の角度から再発見したような感覚」 |
| N3 | **解像度の実感**：自分の知る世界が広がり、細かくなっていくのが見える | 「世界の解像度が上がっていく」 |
| N4 | **確かさ**：事実が本当かどうかを徹底して確認でき、出典をたどれる | 回答1・追加回答 |
| N5 | **いつでも気軽に**：暇なときにぱっと開き、何か面白いものに出会える | 回答2 |
| N6 | **知らないものへの寄り道**：言葉から言葉へたどるうちに、知らなかったものを次々に発見する | 追加回答（Wikipediaのリンクのように） |

すべてのニーズを満たすことを目指す（回答3：全部）。
ただし設計の中心は **N1（つながる瞬間）** に置き、他のニーズはそれを支えるものとする。

## 1-5. プロダクトの目的

1. **つながりを体験させる**：知識がつながる心地よさを、見て・触って感じられるようにする
2. **出会いを用意する**：開いたら、自分が登録した知識から面白い発見が差し出される
3. **確かな知識の蓄積**：一つひとつの事実を検証し、出典とともに残す。信頼できる自分だけの百科事典を育てる
4. **寄り道の楽しさ**：知識の説明の中の言葉から、別の知識へ次々にたどれるようにする
5. **世界の広がりを可視化**：知識が増えるほど宇宙が豊かになっていく様子を見せる

長期的な目的としては、価値が確認できた後に一般公開や収益化を検討する。ただし今は追わない。

## 1-6. 守る原則（迷ったときはこの順で優先）

1. **知ることの幸福を深めるか**（1-0が最上位の判断基準）
2. **本当かどうかを徹底して確認する（ファクトチェック）**
   - 事実には出典を明記し、確認できたかどうかの状態をはっきり示す。
   - 未確認のもの・異論があるものは、確認済みの事実と見分けられるようにする。
   - 解釈（自分の発見や考え）は載せてよい。ただし必ず**「意見」として事実と区別**する。
3. **意味のあるつながり**
   - 線を引くだけでなく、「なぜつながるか」を残す。
4. **自分の手で登録する楽しさを奪わない**
   - AIは提案するだけで、確定は人がする。
5. **いつでも気軽に**
   - iPhoneで片手でも、数秒で楽しめる。
6. **データは自分のもの**
   - 端末内に保存し、いつでもJSONで持ち出せる。

## 1-7. 成功の定義（どうなったら「価値がある」と言えるか）

1か月使った時点で、次を満たしていれば成功とする（数値は仮）。

- **気軽さ**：勉強目的ではなく、暇なときに自分から開いた日が週3日以上ある
- **蓄積**：知識が50個以上ある
- **つながり**：異なるカテゴリー間のつながりが10本以上ある
- **確かさ**：事実の8割以上が「確認済み」の状態になっている
- **寄り道**：説明文の言葉から別の星へたどり、知らなかった知識に出会ったことがある
- **体験**：「これとこれがつながるのか」と感じた瞬間が実際にあった（主観で振り返る）

## 1-8. やらないこと（戦略上の境界）

- 意見を事実と混ぜて表示しない（意見は載せてよいが、必ずそれとわかる形にする）
- 日記・感想の記録帳にはしない
- 汎用のメモアプリやノートアプリにはしない
- タスク管理やスケジュールの機能は持たない
- 当面は、他人との共有・SNS的な要素を作らない
- AIに知識を自動で整理・確定させない

## 1-9. プラットフォーム戦略

- Web版を先に完成させ、価値を検証する
- 価値が確認できたらアプリに翻訳する
- 戦略・要件・構造の3層は、両方で共通にする

## 次の層（要件）に持ち越す論点

方向は決まったので、具体的な扱いは第2層で決める。

1. **事実と意見の区別**（方針は決定：解釈は「意見」として載せてよい）
   - 例1：「プラトンはソクラテスの弟子」は事実。出典で確認する。
   - 例2：「無知の知と科学的懐疑は似ている」は意見。意見として明示する。
   - 第2層では、区別の具体的な方法を決める（確認の状態をどう分けるか、など）。
2. **ファクトチェックの方法**
   - 何をもって「確認済み」とするか（出典の数、出典の信頼性 など）。
   - AIはどこまで手伝えるか（反対の根拠や出典の候補を探す、など）。
3. **言葉から言葉へたどる仕組み**（Wikipediaのリンクのような体験）
   - 説明文の中の言葉を押すと、その言葉の星へ移動できる。
   - まだ登録されていない言葉は「まだ知らない星」として見せるか。
   - 説明文の中のリンクと、星をつなぐ線（関係性）をどう対応させるか。
4. **出典の形**
   - URLだけか、書籍名・ページなども入れるか。
   - 1つの知識に出典を複数付けられるか。
5. **「発見を差し出す」仕組み**
   - 開いたときに何を見せるか（例：今日のつながり、忘れていた星、遠い分野同士の線）。
6. **知識の粒度**
   - 1つの星にどこまで入れるか（人物・概念・出来事・用語 など）。
