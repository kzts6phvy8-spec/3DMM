# UX設計の進め方（5レイヤー）

Jesse James Garrett の「UXの5段階モデル」に沿って、下の層から順に決めていく。
下の層が決まらないうちに上の層（見た目）を決めない。

| 層 | 名前 | 問い | 状態 |
|---|---|---|---|
| 5 | 表層（Surface） | どう見えるか（色・光・質感） | 未着手 |
| 4 | 骨格（Skeleton） | どこに何を置くか（画面配置・ボタン） | **草案・確認待ち** → [04-skeleton.md](./04-skeleton.md) |
| 3 | 構造（Structure） | どうつながり、どう動くか（情報の構造・操作の流れ） | **確定** → [03-structure.md](./03-structure.md) |
| 2 | 要件（Scope） | 何を作り、何を作らないか（機能・コンテンツ） | **確定** → [02-scope.md](./02-scope.md) |
| 1 | 戦略（Strategy） | なぜ作るのか、誰のためか | **確定** → [01-strategy.md](./01-strategy.md) |

## 土台の3層（戦略・要件・構造）

- 言葉だけで定義する。画面の絵やコードは描かない。
- 端末（Web / iPhoneアプリ）に依存しない言葉で書く。
- 1層ずつ確定させてから次へ進む。

## プラットフォームの順序

1. **Web版を先に完成させる**（iPhoneのSafariで快適に使えるWebアプリ）
2. **後からアプリ（iOSネイティブ等）に翻訳する**

翻訳しやすくするため、次のように役割を分ける。

- 戦略・要件・構造の3層は、Webとアプリで**共通**にする。
- 骨格・表層の2層だけを、端末ごとに作り分ける。
- コードでも、データと操作（store / storage）は画面と切り離しておく。
