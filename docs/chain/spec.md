- コード：`src/chain/`（データ `data/`・決まりと検証 `engine.ts`・画面 `App.tsx` `MapView.tsx`・地図の配置 `layout.ts`）

## 1. ゲームのコンセプト

知識と知識のつながりをたどり、スタート地点からゴール地点までの最短経路を探す探索型ゲーム。
プレイヤーは全体像が分からない状態からスタートし、現在地に接続された知識を選択することで、少しずつネットワークを明らかにしていく。

## 2. 確定ルール

| 項目 | 仕様 |
|---|---|
| 探索方式 | 探索しながら全体を明らかにする |
| 開始・目的地 | 最初から表示 |
| 選択肢 | 隣接ノードの名称を表示 |
| 移動 | 接続されたノード間を双方向に移動 |
| 再訪問 | 可能 |
| 移動コスト | 1回につき1手 |
| 経路 | ゴールに至る経路は複数存在 |
| 行き止まり | 存在する |
| 目標 | 最少手数でゴールに到達 |
| 解説 | クリア後に表示 |
| 全体マップ | クリア後に公開 |

## 3. ゲームの進行

1. ステージ開始：スタート地点とゴール地点が提示される。
2. 隣接ノードを表示：現在地に直接つながっている知識の名称が表示される。
3. 知識を選択：選んだノードへ移動し、新しい隣接ノードが開示される。
4. ネットワークを探索：再訪問も利用しながら、ゴールへの経路を探す。
5. ゴール到達：移動手数と最短手数を比較する。
6. 解説・全体マップ：経路上の知識の関係や、別の経路を確認する。

## 4. 最初の試作品で実装する機能（すべて実装済み）

- ステージ選択・開始
- スタートとゴールの表示
- 隣接ノードの表示
- ノードの選択・移動
- 移動履歴の記録（「たどった道」）
- 手数のカウント
- 再訪問処理
- ゴール到達判定
- 最短手数の算出
- クリア後の全体マップ表示（自分の道＝黄色、最短の道＝水色。知識を押すと説明とつながりの理由）

## 5. データ構造（`src/chain/types.ts`）

- ノード：名称、説明、分野、出典（＋行き止まりとして意図したか `deadEnd`）
- 接続：接続元、接続先、関係の種類、接続理由、根拠資料
- 接続は双方向として扱う。
- AIによる接続候補の提案は将来機能。初期版では人間が確認したデータだけを使う。
  - ネットワークに `reviewed`（人間が確認したか）を持つ。Claude が下書きした段階は `false`。利用者が確認したら `true` にする。
  - `false` の間は、ステージ選択の画面に「データは確認中です（下書き）」と出す。

## 6. 自動検証（`src/chain/engine.ts` の validateNetwork・validateStage）

| 調べること | 決まり |
|---|---|
| スタートからゴールへの経路が存在するか | なければエラー |
| 最短手数はいくつか | 3〜7手の範囲外ならエラー |
| 経路が複数あるか | 同じ知識を2度通らない経路が1本だけならエラー |
| 行き止まりは意図したものか | つながりが1本だけの知識は、`deadEnd: true` が付いていなければエラー |
| 接続に矛盾や重複がないか | 同じ2つの知識の接続（逆向きも同じとみなす）・自分自身への接続・存在しない知識への接続はエラー |
| 孤立 | どこにもつながらない知識・ほかと切り離されたまとまりはエラー |
| 中身 | 名称・説明・出典・接続理由・根拠資料が空ならエラー |

検証に通らないステージは、画面で選べない（理由を表示する）。

## 実装で補ったこと（仕様にないもの。不要なら外す）

- つながっている知識のうち、ゴールには「ゴール」、一度通った知識には「通った」と小さく表示する。
- 「最初からやり直す」ボタン。
- ステージごとの最高記録（端末に保存）。
- つながっている知識は名前の順に並べる（並び順が手がかりにならないように）。
- スタートとゴールは、よく知られた知識から選ぶ（難しい言葉だと推測できないという指摘への対応）。
