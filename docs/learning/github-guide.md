# GitHub と Claude Code の使い方ノート

このプロジェクトで実際に使ったものから順に、言葉と操作を記録していく。
新しい言葉が出てきたら、ここに追記する。

---

## 1. まず全体像：ファイルはどこにあるのか

```
 Claude Code の作業場所（クラウド）        GitHub（インターネット上の保管庫）
 ┌───────────────────┐   push →    ┌──────────────────────┐
 │ コードを書く・試す │ ─────────→ │ リポジトリ               │
 │ （しばらく使わない │             │  ├ main ブランチ（本番） │
 │   と消える）       │             │  └ 作業ブランチ          │
 └───────────────────┘             └──────────────────────┘
                                                  │ main に入ると
                                                  ▼
                                          GitHub Pages（公開）
                                          → iPhone で開ける
```

- Claude Code の作業場所は**一時的**なもの。消えても困らないよう、こまめに GitHub に保存（push）する。
- GitHub に置いたものは**ずっと残る**。変更の履歴もすべて残る。

## 2. 用語集

| 用語 | 一言でいうと | このプロジェクトでは |
|---|---|---|
| **Git（ギット）** | ファイルの変更履歴を記録する仕組み | すべてのコードと文書の履歴を記録している |
| **GitHub（ギットハブ）** | Git の記録をインターネット上に置いておけるサービス | `kzts6phvy8-spec/3DMM` に置いている |
| **リポジトリ（repository）** | 1つのプロジェクトのファイルと履歴をまとめた箱 | `3DMM` がこのプロジェクトのリポジトリ |
| **コミット（commit）** | 「ここまでの変更」を1つの記録として保存すること。ゲームのセーブに近い | 例：「最初のプロトタイプを追加」「戦略の層を更新」 |
| **プッシュ（push）** | 手元のコミットを GitHub に送ること | Claude Code の作業場所 → GitHub |
| **ブランチ（branch）** | 本番に影響を与えずに作業するための枝分かれ。並行世界のようなもの | 本番は `main`、作業用は `claude/determined-carson-caf0cd` |
| **main（メイン）** | 本番のブランチ。ここにある内容が正式版 | GitHub Pages で公開されるのは main の内容 |
| **プルリクエスト（Pull Request／PR）** | 「作業ブランチの変更を main に入れてもいいですか？」という提案書。変更点を確認できる | PR #1 で、プロトタイプと戦略の文書を提案中 |
| **マージ（merge）** | プルリクエストの変更を main に取り込むこと | PR #1 をマージすると main に入る |
| **GitHub Actions（アクションズ）** | GitHub 上で自動作業をさせる仕組み | main が更新されたら、アプリを組み立てて公開する |
| **GitHub Pages（ページズ）** | リポジトリの中身を Web サイトとして公開する無料機能 | iPhone で開くための公開場所 |
| **ビルド** | 書いたコードを、ブラウザで動く形にまとめる作業 | GitHub Actions が main の更新のたびに自動でビルドする |
| **デプロイ** | ビルドしたものを公開場所に置くこと | GitHub Pages へのデプロイ |
| **プライベート／パブリック** | リポジトリを自分だけ見られるか、誰でも見られるか | 3DMM は今プライベート。無料プランの GitHub Pages はパブリックのリポジトリでしか使えない |
| **試しブランチ** | 案を見比べるためだけに作る、一時的なブランチ | `try/layout-a`・`b`・`c` で、ボタンの置き場所の3案を見比べる |
| **ワークフロー** | GitHub Actions に「何を・いつ・どの順で」させるかを書いた設定ファイル | `.github/workflows/deploy.yml`。main と試しブランチを組み立てて公開する |
| **手動実行** | ワークフローを、プッシュを待たずにボタンで動かすこと | 「Actions」→ ワークフロー名 →「Run workflow」 |
| **API（エーピーアイ）** | 他のサービスの機能を、プログラムから呼び出すための窓口 | 検索結果やAIの答えをアプリの中に表示するには、検索やAIのAPIが必要になる |
| **サーバー** | インターネット上で常に動いているコンピューター。秘密の鍵（APIキー）を安全に預けられる | 今のアプリはサーバーなしで動く。APIを使う段階（R2）で必要になる |

## 3. よくある流れ（このプロジェクトのやり方）

1. あなたが Claude Code に頼む
2. Claude Code が**作業ブランチ**でコードや文書を変更する
3. Claude Code が**コミット**して、GitHub に**プッシュ**する
4. **プルリクエスト**で変更点を確認する
5. あなたが問題なければ**マージ**する → main に入る
6. GitHub Actions が自動で公開する → iPhone で確認できる

**ポイント**：プルリクエストを開いたまま作業ブランチにプッシュすると、追加の変更は**同じプルリクエストに自動で追加される**。作り直す必要はない。

**失敗から学んだこと（PR #4）**：プッシュの直後にマージすると、最後の変更がGitHubに届く前にマージされてしまうことがある。マージの前に、プルリクエストの最新のコミットが手元と同じかを確認する。

## 4. 自分で操作する手順

### プルリクエストを見る・マージする

1. https://github.com/kzts6phvy8-spec/3DMM を開く
2. 上のタブの「**Pull requests**」を押す
3. 見たいプルリクエストのタイトルを押す
4. 「**Files changed**」タブで、変更されたファイルと中身を確認できる
   - 緑：追加された行
   - 赤：削除された行
5. 問題なければ「**Conversation**」タブに戻り、下の方にある緑の「**Merge pull request**」→「**Confirm merge**」を押す

### 公開（GitHub Pages）を有効にする（最初の1回だけ）

1. リポジトリの上のタブの「**Settings**」を押す
2. 左のメニューの「**Pages**」を押す
3. 「Build and deployment」の「**Source**」で「**GitHub Actions**」を選ぶ

### 自動作業（Actions）の結果を見る

1. 上のタブの「**Actions**」を押す
2. 一覧の一番上が最新の作業
   - 緑のチェック：成功
   - 赤の×：失敗（Claude Code に原因を調べてもらう）

### ファイルの中身を読む

1. リポジトリのトップページで、フォルダやファイル名を押していく
   - 例：`docs` → `ux` → `01-strategy.md`
2. `.md` ファイルは、見出しや表が整った状態で表示される

### iPhone の GitHub アプリでの操作

リポジトリの画面（3DMM）からの手順。

- **ブランチを切り替える**：「main」の行の右にある「**ブランチを変更**」を押し、ブランチを選ぶ
- **ファイルを読む**：「**コード**」を押し、フォルダ名・ファイル名を順に押す
- **プルリクエストを見る**：「**Pull Request**」を押し、タイトルを押す
  - 変更されたファイルは「**ファイル変更**」（Files changed）で見られる
- **マージする**：プルリクエストの画面を下までスクロールし、「**Merge pull request**」→「**Confirm merge**」（アプリでは「マージ」と表示されることもある）
- **自動作業の結果を見る**：「**アクション**」を押す

## 5. Claude Code への頼み方のコツ

- **目的を伝える**：「何を作るか」より「なぜ・何のために」を伝えると、判断がずれにくい
- **確認してほしいことを指定する**：「変更前に説明して」「iPhoneの画面で確認して」など
- **保存も頼める**：「コミットして」「プッシュして」「プルリクエストを作って」
- **わからない言葉はその場で聞く**：「〇〇って何？」で大丈夫
